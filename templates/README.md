# Superhuman Docs starter templates

Template-first: start from one of these, then prune every section that does not serve this doc, and add the one it demands. The template decides the frame; you decide the content. Each maps to the design patterns in `superhuman-docs-design` (hero, main+rail, card wall, decision table, timeline, references).

## 1. Launch Plan / GTM OS
For: coordinating a product or feature launch end to end.
Sections: hero (launch name, date, one-line goal, owner, status); objectives + success metrics; workstream card wall (product, marketing, sales, CS); a milestone timeline; a risks decision table; references (brief, assets, tracker).
Patterns: hero + card wall + timeline + decision table + references.

## 2. QBR / Business Review
For: the quarterly number-and-narrative review.
Sections: hero (period, segment, headline verdict); scorecard card wall (attainment, pipeline, retention, forecast); wins and misses in a main+rail; a risk register decision table; a next-quarter timeline; references (dashboards, source data).
Patterns: hero + card wall + main+rail + decision table + timeline.

## 3. PRD / One-pager
For: aligning on what is being built and why.
Sections: hero (problem, owner, status); context + goal; a requirements decision table (must / should / could); scope + non-goals in a main+rail; a milestones timeline; open questions; references.
Patterns: hero + decision table + main+rail + timeline + references.

## 4. Strategy Memo
For: making an argument and driving a decision. Keep this the most blank-minded of the set.
Sections: hero (the eigenquestion or the ask); a TL;DR verdict callout; the case in a main+rail (reasoning in the rail); an options decision table with the recommendation flagged; what we considered and rejected; references.
Patterns: hero + main+rail + decision table + references.

## 5. Account Plan
For: the strategic read on a target or key account.
Sections: hero (account, ARR or stage, verdict, owner); a buying-committee card wall; a whitespace / expansion decision table; a mutual action plan timeline; risks + next move; references (CRM, notes, deck).
Patterns: hero + card wall + decision table + timeline + references.

## 6. Meeting Notes to Action Items
For: turning a call into owned next steps.
Sections: hero (meeting, date, attendees, one-line outcome); a decisions callout; discussion in a main+rail; an action-item decision table (owner, due, status); references (recording, related docs).
Patterns: hero + main+rail + decision table + references.

## 7. Weekly Update
For: the recurring team or exec status. The one reached for most, so keep it ruthlessly short.
Sections: hero (week, owner, one-line status); a metrics card wall; shipped / in-progress / blocked; an asks decision table; references.
Patterns: hero + card wall + decision table.

## 8. Team Hub / Wiki Home
For: the front door to a team's docs.
Sections: hero (team, mission, quick links); a navigation card wall to sub-pages; owners / directory in a main+rail; live trackers (linked table views); references.
Patterns: hero + card wall + main+rail + references.

## Using a template with the build process
Pick the template that matches the doc-type, run the objective-first prune, build the substance via the MCP, and finish the composition in the UI (the two-pass model). The eval adds one check: did we adapt the template rather than fill it in like a form. The report notes which template was used and what was pruned or added.
